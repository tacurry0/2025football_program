# trapp GAS v6：J2/J3・カップ戦・試合詳細（2026/27）

## 導入

1. 既存GASの取得コードを `JLeague.gs` 全文で置き換え、保存する。V8ランタイムを使用。同名の関数を別ファイルに残さない。
2. `test` を実行して必要な権限を許可する。J2/J3の順位表・結果、ルヴァン・天皇杯の結果の計6件で `status:200`, `stale:false` を確認する。
3. `testDetail` を実行し、新潟の直近試合の選手・審判などの詳細を確認する。
4. 「デプロイ」→「デプロイを管理」→既存Webアプリを編集→バージョン「新バージョン」→デプロイ。既存の実行ユーザー・ブラウザから取得できる公開範囲を引き継ぐ。
5. アプリを再読み込みする。同じデプロイの更新ならURLは維持される。別デプロイを作った場合は `../league-data.js` の `GAS_URL` も変更する。

Google公式: https://developers.google.com/apps-script/concepts/deployments#edit_a_versioned_deployment

保存だけでは既存Webアプリに反映されない。GitHub更新とGASデプロイは別作業。

## API

- 順位表: `?type=standings&league=j2&season=2026_2027`（j2 / j3）
- 結果: `?type=results&league=leaguecup&season=2026_2027`（j2 / j3 / leaguecup / emperor）
- 詳細: `?type=detail&path=/match/leaguecup/2026/090202&season=2026_2027`
- 強制更新: `nocache=1`。通常は30分キャッシュ。旧 `all` / `playoff` は未対応。

JSONの `status` を判定する（ContentServiceの実HTTPステータスではない）。成功は `schemaVersion:2`, `status:200`, `season`, `league`, `fetchedAt`, `stale`, `complete:true`, `data`。公式取得失敗時は前回正常データを元の取得日時で `stale:true` として返す。正常データがなければ503、不正な引数は400。

詳細は `data[0]` に返す。先発・控え（名前／背番号／ポジション／選手ID）、監督、得点者、交代、警告・退場、審判、会場、観客数、天候・気温・湿度、PKを取得する。公開されていない項目は空欄。先発が両チーム11人の場合に `detail_complete:true`。天皇杯などで交代相手の対応関係が公開されていない場合はIN/OUTを個別に記録し、組み合わせは推測しない。試合詳細URLは対応4大会・2026/27シーズンの形式に限定している。

未終了試合の得点はnull、0–0は数値0。PKは本体の得点と別管理し、PK負けを通常の引き分けとして表示しない。

## 取得方式・保持

公式の `/{league}/standings/?year=2026-27` と `/{league}/match/?startdate=...&enddate=...&category=...` を使用。天皇杯は `/{j1,j2,j3}/match/search-list/?category=emperor&startdate=...&enddate=...` の3ページを統合する。天皇杯の対象はJリーグ所属クラブが出場する公式掲載試合（`scope:jleague_clubs`）。地域代表同士の試合の全網羅は対象外。

ページ内のNext Flight JSONを参照解決して読み、ダウンロードしたJavaScriptは実行しない。大会は公式試合URLで区別する。

結果は2026年8月から当日まで、最大3か月ずつ取得。初回は経過月全部、以降は当月・前月・未終了試合のある月・過去月の持ち回り再確認。月別結果を試合IDで更新し、完了済み試合の突然の欠落はエラー扱いにする。過去の得点訂正も再確認で反映。

順位表・結果はgzip/base64圧縮し、Script Propertiesへ7000文字ずつ分割保存。v5の正常取得済み結果も移行時に読み込める。詳細は短期キャッシュと、最大32試合の永続保存（1件8500文字未満）を使用。`clearCache()` は順位表・結果の短期キャッシュを削除し、正常データを残す。詳細の明示更新は `nocache=1` またはアプリの「詳細を更新」。

公式サイトの内部構造が再変更された場合はパーサー修正が必要。現在は2026/27専用で、次季はGASの `JL` とクライアントの `SEASON`・データパスを一緒に変更する。

## 画面と履歴

- 日程は従来の暦年別（2026、2027…）。2026/27専用タブは設けない。データ内部ではシーズン・大会を識別する。
- スマホ順位表は順位・チーム・勝点・試合数・得失点差を常時表示。「勝敗・得失点を見る」で残りを縦に展開する。PCは全列表示。
- カレンダー下部の「年月を隠す／年月を表示」で年・月ナビを開閉し、設定を保存する。日程一覧のナビは維持する。
- 結果から未登録の新潟・熊本戦を補完し、未定だった相手を確定する。変更前の `storage_date` / `storage_opponent` を保持し、観戦・メモの保存キーを引き継ぐ。
- 試合を開くとGASから詳細を1試合ずつ取得する。取得中もメモ編集を維持。取得済み詳細はブラウザに保存し、再取得失敗時も表示する。
- 百年構想の結果・年別詳細は引き続き履歴として利用。百年構想順位表の保存分は2026年4月17日取得で、最終順位ではない。

